# Defect Lens engineering case study

The intended operator checks one gray tabletop plate for a missing fastener or a visible surface mark. A manual process compares the photograph against a known good assembly, decides whether it is usable and records an explanation. Defect Lens makes that comparison inspectable: an aligned image, appearance score, spatial evidence, explicit uncertainty and a correction history remain tied to a frozen model revision. This is a portfolio simulation, not a customer pilot; no time saving is measured or claimed.

The first constraint was reproducibility. The sample generator assigns specimen/session groups before rendering 216 original procedural images, with 36 good training views, 90 validation views and 90 held-out views. Only validation chooses score thresholds, localization thresholds and the heatmap scale. Procedural groups are generated identities rather than independent photographed assemblies; their bootstrap intervals do not establish real-world variation.

The baseline aligns plate edges with ECC and compares against a median good reference after bounded brightness correction. The second method uses actual ResNet18 IMAGENET1K_V1 layer2 features, a seeded 4,096-vector bank and block nearest-neighbor distances. It preserves the common 256-square geometry and runs on CPU. The model card separates checkpoint execution from photographic evidence. The [frozen measured report](../reports/fixture-v1/report.md) contains 90 held-out images per method. Both detected 36/36 labelled defects with no false rejects on 36 good examples. Difference required 21/90 reviews (23.3%); the feature method required 54/90 (60.0%), including every good example. Mean mask IoU was 1.000 versus 0.213, and warm pipeline p95 was 16.51 ms versus 32.29 ms. These observations support retaining the difference default for this simple geometry. They do not establish performance on photographs.

An instructive failure is the blurred fixture: it can resemble a different object locally, so the system forces review and suppresses a misleading heatmap. The interface explains this limitation instead of assigning a cause. Human feedback is append-only, keeps the original decision and does not become a training label automatically.

Operational behavior matters as much as the scorer. SQLite transaction boundaries protect admission, result completion and versioned corrections. Retries check their key/hash before readiness or version conflicts. A supervised child has a time/RSS ceiling and one restart budget. The real restart test saves a correction, suspends the owned worker, interrupts processing, restarts and retrieves the correction while the unfinished job is explicitly INTERRUPTED. Browser tests cover good/defect/blur uploads, overlay controls, keyboard correction and reload in both palettes and mobile/desktop layouts.

The browser run exposed a concrete selection defect: clicking the selected queue item cleared its result without triggering a refetch. A failing browser assertion reproduced it; retaining the existing selection fixed it. The process run also exposed a shutdown timing race, resolved by waiting for registered children to exit before declaring success. Both findings improved the complete workflow rather than only a type check.

There are no owned-photo results. A separate capture recipe requires genuinely distinct physical assemblies, exclusive sessions, explicit rights, human truth/mask reviews and recorded setup. The release boundary is local software evidence with an honest photographic gate, not an industrial deployment claim.
